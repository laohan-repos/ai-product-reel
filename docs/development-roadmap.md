# AI Product Reel 开发路线

> 本文档用于指导学习者使用 Codex，从零逐步实现 AI Product Reel。
>
> 配套需求文档：[product-requirements.md](./product-requirements.md)

## 1. 路线目标

这条开发路线遵循“先跑通数据，再接入 AI，最后完善体验”的顺序。每个阶段都应产生一个可以独立运行、验证和提交的版本，避免一次让 Codex 修改过多模块。

完成全部阶段后，学习者将得到一个能够执行以下完整流程的应用：

```text
创建作品
  → 上传参考视频和产品图片
  → 生成两类预览图
  → 分析参考视频结构
  → 生成产品故事板
  → 生成并选择关键帧
  → 生成并选择视频片段
  → 合成最终视频
  → 生成剪映草稿
```

## 2. 开发原则

### 2.1 每次只实现一个闭环

一次 Codex 任务应包含一个明确目标，例如“完成作品 CRUD”，不要同时要求它实现作品、素材、模型调用和视频合成。

### 2.2 先定义验收，再开始编码

每个任务至少要说明：

- 用户可以执行什么操作。
- 数据应该如何变化。
- 失败时应该出现什么结果。
- 需要运行哪些验证命令。

### 2.3 保持 Git 提交粒度

每完成一个可以运行的功能闭环就提交一次。提交前应查看 diff，并确认没有密钥、数据库、生成媒体和缓存文件。

### 2.4 遵守当前 Next.js 版本规则

Codex 修改 Next.js 代码前，必须先阅读 `AGENTS.md`，并查看 `node_modules/next/dist/docs/` 中与当前任务相关的文档。

### 2.5 AI 输出始终需要校验

模型响应不是可信的结构化数据。所有模型调用都需要处理：

- 空响应。
- 非预期 JSON 或 Markdown。
- 超时和网络失败。
- 上游返回非 2xx 状态。
- 缺少字段或内容无法解析。

## 4. 阶段 0：环境与项目基线

### 目标

建立可重复的开发环境，让项目能够启动、检查和构建。

### 开发任务

1. 安装 Node.js 22.13 或更高版本。
2. 安装 FFmpeg 和 FFprobe。
3. 创建 Next.js 16、React 19、TypeScript 项目。
4. 配置 Tailwind CSS、shadcn/ui、Oxlint 和 Oxfmt。
5. 建立 `.gitignore` 和 `.env.example`。
6. 添加 `AGENTS.md`，要求 Codex 读取当前 Next.js 文档。
7. 初始化 Git 仓库并建立 `main` 分支。

### 验收标准

- `npm install` 成功。
- `npm run dev` 可以启动。
- 首页可以在浏览器打开。
- `npm run build` 成功。
- `.env`、`.data`、`.next`、`node_modules` 和 `*.tsbuildinfo` 不会进入 Git。

### Codex 提示词示例

```text
请检查当前目录并建立 AI Product Reel 的 Next.js 开发基线。
开始前先阅读 AGENTS.md 和 node_modules/next/dist/docs 中的项目结构、页面、布局与 Route Handler 文档。

要求：
1. 使用 Next.js 16 App Router、React 19 和 TypeScript 严格模式。
2. 配置 Tailwind、shadcn/ui、Oxlint 和 Oxfmt。
3. 添加安全的 .gitignore 和不包含真实密钥的 .env.example。
4. 不实现业务功能。
5. 完成后运行 lint 和生产构建。
```

### 推荐提交

```text
chore: initialize Next.js project
```

## 5. 阶段 1：静态工作台原型

### 目标

先建立完整的信息架构，让用户能看到项目最终会有哪些步骤。

### 开发任务

1. 创建首页作品列表区域。
2. 创建素材库入口。
3. 创建 `/workflows/[id]` 作品详情路由。
4. 实现十步创作导航。
5. 为每个步骤制作静态卡片、空状态和操作按钮。
6. 实现模型设置弹窗的静态表单。
7. 实现桌面端和移动端布局。

### 页面重点

- 页面顶部明确展示作品名称和当前步骤。
- 左侧或顶部导航可以跳转到不同生成步骤。
- 所有尚未实现的按钮应处于合理禁用状态。
- 不使用假接口制造“已经成功”的结果。

### 验收标准

- `/` 和 `/workflows/1` 均能访问。
- 十个步骤的名称和顺序与需求文档一致。
- 手机尺寸下没有横向溢出。
- 使用键盘可以操作主要按钮和弹窗。

### 推荐提交

```text

```

## 6. 阶段 2：SQLite 与作品管理

### 目标

建立服务端数据层，并首先跑通作品的增删改查。

### 开发任务

1. 使用 `better-sqlite3` 建立数据库连接封装。
2. 默认将数据库保存到 `.data/ai-product-reel.sqlite`。
3. 开启 WAL、外键约束和忙等待。
4. 创建 `workflow_runs` 表。
5. 实现 `/api/workflows` 的 GET、POST、PATCH 和 DELETE。
6. 将首页作品列表接入真实接口。
7. 创建、重命名和删除操作增加校验与反馈。
8. 作品详情路由读取并验证动态参数。

### 实现注意

- SQL 一律使用参数化查询。
- 动态路由参数使用当前 Next.js 推荐的 `params` 或 `useParams`。
- 不要通过解析 `window.location.pathname` 获取作品 ID。
- 不存在的作品返回 404 或展示明确空状态。

### 验收标准

- 创建作品后刷新页面仍然存在。
- 空名称不能创建作品。
- 重命名后列表立即更新。
- 删除作品需要二次确认。
- 输入不存在的作品 ID 不会打开错误作品。

### Codex 提示词示例

```text
本次只实现 SQLite 数据层和作品 CRUD，不处理素材与模型。
请先阅读现有页面、AGENTS.md，以及当前 Next.js 的动态路由和 Route Handler 文档。

验收标准：
1. 作品可以创建、读取、重命名和删除。
2. 刷新后数据仍然存在。
3. 所有输入经过校验，SQL 使用参数绑定。
4. /workflows/[id] 使用当前 Next.js 推荐方式读取参数。
5. 添加必要测试并运行 lint、测试和 build。
```

### 推荐提交

```text
feat: add SQLite workflow management
```

## 7. 阶段 3：素材库与二进制存储

### 目标

让用户可以保存、管理、预览参考视频和产品图片。

### 开发任务

1. 创建 `asset_groups`、`asset_items` 和分块表。
2. 实现参考视频组与产品素材组。
3. 实现 multipart 文件上传。
4. 对文件名、类型、大小和空文件进行校验。
5. 将媒体分块写入 SQLite。
6. 实现独立文件读取 Route Handler。
7. 实现素材预览、改名、下载和删除。
8. 支持产品素材组关联参考视频组。

### 实现顺序

```text
素材组 CRUD
  → 单个文件上传
  → 文件读取与预览
  → 文件删除
  → 多文件上传
  → 组关联
```

### 验收标准

- 上传的图片和视频可以正常预览。
- 列表接口不返回文件 BLOB。
- 文件接口返回正确的 MIME 类型和大小。
- 删除素材组后，关联文件被正确清理。
- 50 MB 左右的视频上传不会使接口直接崩溃。

### 推荐提交

```text
feat: add reusable asset library
```

## 8. 阶段 4：FFmpeg 与预览图生成

### 目标

建立媒体处理基础能力，并生成模型可以理解的视觉总览图。

### 开发任务

1. 创建 FFmpeg/FFprobe 命令封装。
2. 支持通过环境变量覆盖可执行文件路径。
3. 使用 FFprobe 获取视频时长。
4. 根据视频时长计算均匀抽帧时间点。
5. 将抽取的画面合成为参考视频预览图。
6. 将多张产品图片合成为产品预览图。
7. 建立预览图版本表和文件读取接口。
8. 实现预览、切换和删除版本。
9. 所有预览图关联到当前作品。

### FFmpeg 安全要求

- 使用参数数组启动进程，不拼接 shell 命令字符串。
- 为每次任务创建独立临时目录。
- 无论成功或失败都清理临时文件。
- 设置合理的进程超时。
- 将底层错误转换成用户可理解的消息。

### 验收标准

- 参考预览图覆盖视频的开始、中间和结束部分。
- 产品图片方向正确且没有明显拉伸。
- 连续生成多个版本不会覆盖旧版本。
- 损坏视频会得到清晰错误，且数据库中没有残缺记录。

### 推荐提交

```text
feat: generate reference and product overviews
```

## 9. 阶段 5：模型配置与多模态分析

### 目标

接入第一个 AI 能力：分析参考视频结构并生成产品故事板。

### 开发任务

1. 创建 `model_configs` 表。
2. 实现三类模型配置的读取和保存。
3. 实现模型连接测试接口。
4. 封装 OpenAI 兼容的请求地址转换逻辑。
5. 编写参考视频结构分析提示词。
6. 调用多模态模型分析参考预览图。
7. 使用 Markdown 保存和展示分析结果。
8. 结合产品预览图生成产品视频方案。
9. 解析并校验 `Generation N` 段落。

### 开发建议

先使用假模型响应完成数据库和 UI 闭环，再连接真实模型。假响应只能存在于测试或明确的开发模式中。

### 安全要求

- API Key 只在服务端请求上游模型。
- 浏览器读取设置时不返回完整 API Key。
- 模型错误和日志不包含鉴权头。
- Base URL 需要进行格式校验。

### 验收标准

- 模型连接成功和失败都有明确结果。
- 未配置模型时不能发起分析。
- 分析结果和产品方案均可保存多个版本。
- 无法解析的模型响应不会被当作成功方案保存。

### 推荐提交

```text
feat: add multimodal video planning
```

## 10. 阶段 6：关键帧图片生成

### 目标

为故事板中的每个 Generation 生成并管理关键帧候选版本。

### 开发任务

1. 创建关键帧及文件分块表。
2. 从产品视频方案解析 Generation 列表。
3. 为每段生成默认图片提示词。
4. 允许用户在提交前编辑提示词。
5. 将产品参考图片和提示词提交给图片模型。
6. 支持图片 URL 和 Base64 两类上游结果。
7. 下载生成图片并保存到本地数据库。
8. 实现预览、替换、删除和版本选择。
9. 保证同一 Generation 最多一个版本被选中。

### 推荐实现顺序

```text
解析方案
  → 展示提示词
  → 单段图片生成
  → 版本管理
  → 选择约束
  → 多段依次生成
```

### 验收标准

- 每个 Generation 都能独立生成，不互相影响。
- 重新生成不会覆盖历史版本。
- 修改选中版本后刷新页面，选择状态保持不变。
- 上游返回超大文件或非图片内容时请求失败并提示原因。

### 推荐提交

```text
feat: generate and select product keyframes
```

## 11. 阶段 7：异步视频生成

### 目标

基于选中的关键帧生成视频，并可靠管理长时间运行的异步任务。

### 开发任务

1. 创建产品视频和文件分块表。
2. 为每个 Generation 生成默认视频提示词。
3. 提交图生视频任务并保存任务 ID。
4. 建立排队、处理中、成功和失败状态。
5. 实现单任务状态刷新接口。
6. 前端只轮询未完成任务。
7. 成功后下载并保存视频文件。
8. 实现失败重试、预览、删除和版本选择。
9. 页面刷新后自动恢复未完成任务的查询。

### 状态机建议

```text
queued → processing → completed
                   ↘ failed

failed → retry → queued
```

不允许从 `completed` 自动回到 `processing`。状态更新应依据上游任务 ID，并验证任务属于当前记录。

### 验收标准

- 提交任务后页面不会长时间阻塞。
- 刷新页面后仍能继续查询任务。
- 已完成任务不会继续轮询。
- 单个视频失败不会停止其他视频任务。
- 同一 Generation 最多一个视频版本被选中。

### Codex 提示词示例

```text
本次实现异步图生视频任务，不修改关键帧生成和最终视频合成。
请先分析当前图片版本选择逻辑和视频模型接口协议。

要求：
1. 提交任务后立即保存上游 task_id 和 queued 状态。
2. 使用独立 PATCH 操作刷新状态。
3. 只轮询未完成任务，页面刷新后可恢复。
4. 成功后校验媒体类型和体积，再保存视频。
5. 支持失败提示、重试、删除和单选。
6. 为状态转换和异常响应添加测试。
```

### 推荐提交

```text
feat: add asynchronous shot video generation
```

## 12. 阶段 8：最终视频合成

### 目标

将用户选择的视频片段按故事板顺序合成为最终成片。

### 开发任务

1. 创建最终视频及分块表。
2. 合成前检查所有必要 Generation 是否已选择视频。
3. 按 Generation 序号排序，不能依赖数据库插入顺序。
4. 使用 FFmpeg 统一视频参数。
5. 拼接视频并保存输出文件。
6. 实现成片播放、下载、版本列表和删除。
7. 为失败合成清理数据库与临时文件。

### 验收标准

- 合成顺序与故事板一致。
- 输出 MP4 能在浏览器和常见播放器中播放。
- 输入分辨率或编码不同也能生成统一成片。
- 缺少分镜或文件损坏时不生成残缺版本。

### 推荐提交

```text
feat: compose selected shots into final video
```

## 13. 阶段 9：剪映草稿生成

### 目标

将生成视频和补充媒体组织为可继续编辑的剪映草稿。

### 开发任务

1. 创建草稿素材和草稿记录表。
2. 实现视频、音频和图片附件上传。
3. 使用 FFprobe 获取视频与音频时长。
4. 建立剪映草稿提示词编辑器。
5. 调用草稿生成服务。
6. 保存草稿地址、提示地址、状态和错误。
7. 实现草稿历史记录查看和删除。

### 环境变量

```text
CAPCUT_MATE_BASE_URL
CAPCUT_MATE_API_KEY
DRAFT_ASSET_BASE_URL
```

### 验收标准

- 本地服务配置正确时可以创建草稿。
- 远程服务无法访问本地素材时给出明确提示。
- 草稿服务错误不会删除已上传素材或最终视频。
- API Key 不出现在客户端和日志中。

### 推荐提交

```text
feat: create editable CapCut drafts
```

## 14. 阶段 10：批量生成

### 目标

将单作品流程编排为多个产品素材组的批量任务。

### 开发任务

1. 选择一个参考素材组和多个产品素材组。
2. 为每个产品素材组创建独立作品。
3. 编排产品预览图、方案、关键帧和视频生成。
4. 展示每个素材组、每个步骤的状态和说明。
5. 单个任务失败后继续执行其他任务。
6. 防止重复点击产生重复作品或重复请求。
7. 完成后提供每个作品的详情入口。

### 验收标准

- 三个素材组可以独立显示进度。
- 一个素材组失败不会阻止另外两个完成。
- 页面可以看出失败发生在哪个步骤。
- 批量完成结果与逐个手动执行结果一致。

### 推荐提交

```text
feat: add batch product video workflow
```

## 15. 阶段 11：测试、重构与安全收尾

### 目标

将“能够演示”提升为“能够维护和继续扩展”。

### 15.1 前端重构

- 按业务域拆分作品、素材、方案、关键帧和视频组件。
- 将数据请求提取为 hooks 或清晰的服务模块。
- 集中管理弹窗、加载状态和错误消息。
- 消除超大页面组件和重复状态。
- 使用 Next.js 客户端导航，避免不必要的整页刷新。

### 15.2 后端重构

- 将数据库初始化和迁移集中管理。
- 将模型协议封装成适配器。
- 将文件分块、模型请求和错误转换提取为共享模块。
- 为长任务增加超时、重试和幂等控制。
- 对资源归属关系进行统一校验。

### 15.3 测试建设

- 为纯函数编写单元测试。
- 为 Route Handler 编写集成测试。
- 使用固定模型响应测试解析逻辑。
- 使用短视频夹具测试 FFmpeg 流程。
- 增加一条完整端到端主流程。

### 15.4 安全检查

- 确认 API Key 不会通过 GET 接口返回。
- 检查 Git 历史是否包含密钥和数据库。
- 限制上传文件类型、数量和体积。
- 限制远程媒体下载的协议、目标地址、超时和大小。
- 公网部署前增加身份认证与作品权限。

### 最终验收命令

```bash
npm run format
npm run lint
npm test
npm run build
```

如果项目尚未配置 `test` 脚本，应先选择测试框架并补充脚本，不应跳过测试。

### 推荐提交

```text
refactor: harden and test generation workflow
```

```text
 ├─ codex/video-overview
 ├─ codex/multimodal-planning
 ├─ codex/keyframe-generation
 ├─ codex/video-generation
 └─ codex/final-composition
```

每个分支只处理一个阶段。合并前检查：

1. 功能是否满足该阶段验收标准。
2. 是否修改了任务范围外的代码。
3. 是否包含数据库、密钥、缓存或大体积测试输出。
4. Lint、测试和构建是否通过。
5. 是否更新相关文档和环境变量示例。

## 18. 学习者检查清单

每完成一个阶段，学习者需要能够回答：

- 我本阶段解决了哪个用户问题？
- 数据从浏览器到数据库经过了哪些模块？
- 哪些输入是不可信的，代码如何校验？
- 操作中途失败会留下什么状态？
- 刷新页面后任务为什么还能恢复？
- 哪些逻辑有自动化测试？
- Codex 修改了哪些文件，我是否读懂了关键代码？
- 如果要回退，本阶段对应哪个 Git 提交？

只有在能够回答这些问题后，再进入下一阶段。

## 19. 路线完成标准

开发路线完成时，应满足：

- 单作品完整生成流程可用。
- 多作品数据严格隔离。
- 素材、图片、视频和成片可以持久化读取。
- AI 配置、调用、解析和错误处理完整。
- 异步视频任务在刷新后可以恢复。
- FFmpeg 合成结果顺序正确且可以播放。
- 剪映草稿生成状态可追踪。
- 批量任务能够隔离失败。
- 没有密钥、数据库和本地生成内容进入 Git。
- 格式化、Lint、测试和生产构建全部通过。
- README、需求文档和开发路线与实际实现一致。
