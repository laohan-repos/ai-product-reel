# AI Product Reel 产品需求文档

> 文档用途：指导学习者使用 Codex 从零实现一个 AI 产品视频创作工具。
>
> 项目仓库：[https://gitee.com/alinec/ai-product-reel](https://gitee.com/alinec/ai-product-reel)

## 1. 项目概述

### 1.1 产品名称

AI Product Reel（同款视频）

### 1.2 一句话介绍

分析参考视频的镜头结构，并结合用户上传的产品素材，自动生成产品关键帧、分镜视频、最终成片和剪映草稿。

### 1.3 产品背景

电商和内容创作者经常需要参考成熟广告视频的节奏与镜头语言，为新产品快速制作相似结构的宣传视频。传统制作流程涉及视频分析、脚本编写、分镜设计、图片生成、视频生成和后期剪辑，沟通与制作成本较高。

本项目将上述流程组织为一个可视化工作台，让用户可以保留参考视频的结构和节奏，同时用自己的产品素材完成新的宣传视频。

### 1.4 教学目标

学习者完成项目后，应能够掌握：

- 使用 Codex 分析需求、拆分任务并持续迭代代码。
- 使用 Next.js App Router 开发前后端一体化应用。
- 设计素材上传、文件读取和版本管理能力。
- 使用 SQLite 保存结构化数据和二进制媒体。
- 接入 OpenAI 兼容的文本、多模态、图片和视频模型接口。
- 处理异步视频任务提交、轮询、失败重试和结果下载。
- 使用 FFmpeg 探测媒体信息并合成视频。
- 将复杂 AI 工作流设计成可理解、可操作的用户界面。

## 2. 产品目标与边界

### 2.1 核心目标

1. 用户可以集中管理参考视频和产品图片。
2. 系统可以将参考视频转换为便于模型理解的预览图。
3. AI 可以分析参考视频并输出结构化镜头方案。
4. AI 可以将原参考视频方案替换成适合当前产品的故事板。
5. 用户可以逐镜头生成、挑选和管理关键帧图片。
6. 用户可以根据关键帧生成视频片段，并查看任务状态。
7. 用户可以挑选视频片段，自动合成完整产品视频。
8. 用户可以生成剪映草稿，继续完成字幕、音频等后期制作。
9. 用户可以创建多个作品，避免不同项目的生成结果混在一起。

### 2.2 非目标

首个版本不要求实现：

- 多用户注册、登录和团队协作。
- 在线支付、套餐和用量结算。
- 自研 AI 模型训练或推理服务。
- 专业非线性视频编辑时间线。
- 云端对象存储和跨设备同步。
- 面向公网的高并发部署能力。

项目默认定位为单用户、本地运行的教学型应用。若部署到公网，必须补充鉴权、密钥保护、存储扩展和任务队列。

## 3. 用户角色与使用场景

### 3.1 用户角色

- 电商运营：为商品快速生成短视频广告。
- 内容创作者：参考优秀视频的结构制作新内容。
- AI 应用开发学习者：学习完整的 AI 多媒体工作流。
- 开发者：测试不同厂商的多模态、图片和视频模型。

### 3.2 典型使用场景

用户找到一条喜欢的产品广告视频，将其上传到素材库；然后上传自己的产品图片。系统生成参考视频预览图并分析镜头结构，再结合产品图片生成新的故事板。用户逐个生成关键帧和视频片段，挑选满意的版本，最后合成为完整视频或导出剪映草稿继续编辑。

## 4. 核心业务流程

```text
创建作品
  ↓
上传参考视频与产品图片
  ↓
生成参考视频预览图和产品预览图
  ↓
分析参考视频镜头结构
  ↓
生成产品视频方案
  ↓
生成并挑选关键帧图片
  ↓
生成并挑选分镜视频
  ↓
合成最终视频
  ↓
生成剪映草稿或下载成片
```

## 5. 功能需求

### 5.1 作品管理

#### 功能说明

作品是一次完整视频创作过程的容器。不同作品的数据必须相互隔离。

#### 功能要求

- 展示作品列表、名称、创建时间、更新时间和当前状态。
- 支持创建、重命名和删除作品。
- 创建后进入 `/workflows/{id}` 作品详情页。
- 删除作品时显示二次确认。
- 记录作品当前进行到的步骤。
- 列表中展示预览图、方案、关键帧和视频的数量。

#### 验收标准

- 创建两个作品后，分别上传和生成的数据不会互相出现。
- 刷新页面后，作品和当前数据仍然存在。
- 删除作品后，与该作品关联的业务记录能够被清理。

### 5.2 素材库

#### 功能说明

素材库保存可复用的参考视频和产品图片。参考视频素材组可以关联一个产品素材组。

#### 功能要求

- 支持创建参考视频素材组和产品素材组。
- 支持上传视频与多张产品图片。
- 支持修改素材组名称和素材名称。
- 支持预览、下载和删除素材。
- 显示文件名、媒体类型、大小和上传时间。
- 上传时校验文件类型和空文件。
- 产品素材组可以关联到指定参考视频素材组。

#### 验收标准

- 视频和图片上传后可正常预览。
- 重启开发服务器后素材仍然存在。
- 删除素材组前有明确提示，确认后关联素材一并删除。
- 不支持的文件类型会返回清晰错误信息。

### 5.3 模型配置

#### 功能说明

系统通过配置连接不同的 AI 服务，分为多模态模型、图片模型和视频模型三类。

#### 配置字段

- 模型类型：`multimodal`、`image` 或 `video`。
- 模型 ID：实际调用的模型名称。
- Base URL：兼容服务的基础地址。
- API Key：服务鉴权密钥。

#### 功能要求

- 使用独立设置弹窗管理三类模型。
- 支持保存配置和测试连接。
- API Key 输入框默认隐藏内容。
- 连接测试需展示成功或失败原因。
- 生成操作缺少必要配置时，应阻止请求并提示用户。

#### 安全要求

- API Key 只能在服务端用于上游模型请求。
- 面向公网部署时，读取配置的接口不得向浏览器返回完整 API Key。
- 日志、错误消息和生成记录不得包含完整密钥。
- `.env`、SQLite 数据库和本地运行状态必须加入 `.gitignore`。

### 5.4 参考视频预览图

#### 功能说明

系统从参考视频中提取多个代表性画面，合成为一张总览图，作为后续多模态分析输入。

#### 功能要求

- 用户可以选择一个参考视频。
- 系统根据视频时长均匀抽取画面。
- 抽取帧按时间顺序排列并合成为预览图。
- 支持生成多个版本并切换查看。
- 支持放大查看和删除指定版本。
- 每个版本必须关联当前作品。

#### 验收标准

- 生成结果能够覆盖视频开头、中间和结尾。
- 画面顺序与原视频时间顺序一致。
- 生成失败时不会写入不完整记录。

### 5.5 产品预览图

#### 功能说明

系统将同一素材组的产品图片合成为一张预览图，方便模型同时理解产品外观和细节。

#### 功能要求

- 用户选择产品素材组后生成预览图。
- 多张图片按稳定顺序排列。
- 图片保持正确方向，不应明显拉伸。
- 支持多个生成版本、查看和删除。
- 预览图需要关联作品与产品素材组。

### 5.6 参考视频结构分析

#### 功能说明

多模态模型根据参考视频预览图，输出每个镜头的时长、景别、主体、动作、运镜、光线、转场和声音建议。

#### 功能要求

- 用户可以查看和修改分析提示词。
- 请求需携带预览图和提示词。
- 分析结果使用 Markdown 保存和展示。
- 支持保存多个分析版本。
- 模型输出不符合预期时，界面需允许重新生成。

#### 输出至少包含

- 视频整体定位与风格。
- 总时长与画幅建议。
- 分镜编号。
- 每个分镜的建议时长。
- 画面主体与构图。
- 镜头运动与主体动作。
- 光线、色彩和质感。
- 镜头之间的转场关系。

### 5.7 产品视频方案

#### 功能说明

将参考视频结构与产品预览图结合，生成适合当前产品的完整故事板。

#### 功能要求

- 输入参考结构、产品预览图和可选产品补充描述。
- 保留参考视频的节奏和镜头数量，但替换画面主体与叙事内容。
- 每个生成段使用稳定标识，例如 `Generation 1`。
- 每段需提供关键帧描述、视频动作描述和时长。
- 支持查看、选择、重新生成和删除方案版本。

#### 验收标准

- 生成结果能够被程序稳定拆分为多个 Generation 段落。
- 每个段落都具备足够信息供图片模型和视频模型使用。
- 方案明确体现用户产品，不直接复制参考视频中的品牌或商品。

### 5.8 关键帧生成

#### 功能说明

根据产品视频方案中的每个 Generation 段落生成产品关键帧。

#### 功能要求

- 自动从方案中解析 Generation 列表。
- 为每个 Generation 生成可编辑的图片提示词。
- 图片请求需携带产品参考图，保持商品外观一致。
- 每个 Generation 支持生成多个候选版本。
- 支持预览、上传替换、删除和选中一个版本。
- 选中状态在刷新后仍然保留。
- 未生成或未选中关键帧时，视频生成按钮应给出明确提示。

#### 验收标准

- 关键帧与对应方案段落正确关联。
- 同一 Generation 选中新版本后，旧版本自动取消选中。
- 模型请求失败不会影响其他 Generation 已生成的内容。

### 5.9 分镜视频生成

#### 功能说明

使用选中的关键帧作为首帧，向视频模型提交图生视频任务。

#### 功能要求

- 为每个 Generation 生成可编辑的视频提示词。
- 提交任务后保存上游任务 ID。
- 状态至少包括：排队中、处理中、成功和失败。
- 前端定时刷新尚未完成的任务。
- 成功后下载视频并保存到本地数据库。
- 远程结果暂时不可用时不得错误标记为失败。
- 支持失败重试、预览、删除和选择候选版本。
- 生成时长来自方案，缺失时使用安全默认值。

#### 验收标准

- 页面刷新后仍可继续查询未完成任务。
- 上游返回失败原因时，界面展示可理解的信息。
- 每个 Generation 只能有一个当前选中的视频版本。

### 5.10 最终视频合成

#### 功能说明

按照 Generation 顺序，将用户选中的视频片段合成为一个 MP4 文件。

#### 功能要求

- 合成前校验所有必要分镜是否已有选中版本。
- 使用 FFmpeg 统一编码、分辨率、帧率和音视频参数。
- 按方案顺序拼接视频，不得按数据库创建顺序误排。
- 合成结果关联当前作品与方案。
- 支持在线播放、下载和删除。
- 临时文件在成功或失败后都应清理。

#### 验收标准

- 输出文件能被常见浏览器和播放器正常播放。
- 视频顺序、时长和用户选择一致。
- 某个片段损坏时，接口返回具体错误且不生成残缺成片。

### 5.11 剪映草稿

#### 功能说明

将视频、图片、音频和字幕信息发送给剪映草稿服务，生成可继续编辑的草稿。

#### 功能要求

- 用户可以查看和编辑草稿生成提示词。
- 支持附加视频、图片和音频素材。
- 自动探测媒体时长。
- 生成请求需记录状态、草稿地址、提示地址和错误信息。
- 支持查看历史草稿和删除记录。
- 使用远程草稿服务时，素材 URL 必须可被远程服务访问。

### 5.12 批量生成

#### 功能说明

用户选择多个产品素材组后，系统依次完成预览图、方案、关键帧和视频生成。

#### 功能要求

- 展示每个素材组和每个步骤的独立状态。
- 状态包括等待、执行中、完成和失败。
- 单个素材组失败时，不阻塞其他素材组继续执行。
- 完成后提供对应作品入口。
- 批量任务不得重复创建同一作品或重复提交同一步骤。

## 6. 页面与交互要求

### 6.1 页面结构

- `/`：作品列表、素材库入口和批量生成入口。
- `/workflows/{id}`：指定作品的完整创作工作台。

### 6.2 工作台步骤

1. 参考视频
2. 智能抽帧
3. 视频总览
4. 结构脚本
5. 产品参考
6. 故事板
7. 关键帧提示词
8. 关键帧图片
9. 视频提示词
10. 分镜视频

### 6.3 通用交互

- 所有耗时操作显示加载状态，并避免重复提交。
- 成功、失败和校验错误使用统一消息提示。
- 删除操作必须二次确认。
- 图片支持大图预览，视频支持播放和下载。
- 移动端至少能够完成查看、选择和触发生成操作。
- 按钮、表单和弹窗应支持键盘操作及基本无障碍语义。

## 7. 技术需求

### 7.1 推荐技术栈

- Node.js 22.13 或更高版本。
- Next.js 16 App Router。
- React 19 和 TypeScript 严格模式。
- Tailwind CSS 与 shadcn/ui。
- SQLite 与 `better-sqlite3`。
- FFmpeg 与 FFprobe。
- OpenAI 兼容的模型调用协议。

### 7.2 Next.js 开发约束

本项目使用的 Next.js 版本可能包含训练数据之外的新 API。Codex 在修改代码前必须先阅读仓库内 `node_modules/next/dist/docs/` 中与任务相关的文档，不能仅凭旧版 Next.js 经验实现。

### 7.3 数据存储

首个版本使用本地 SQLite：

- 结构化信息保存为普通字段。
- 大型媒体使用分块 BLOB 保存，避免单条 SQL 参数过大。
- 开启 WAL、外键约束和合理的忙等待时间。
- 数据库默认保存到 `.data/ai-product-reel.sqlite`。
- 支持通过 `SQLITE_PATH` 修改数据库位置。

### 7.4 文件与媒体处理

- 上传接口不得一次性无边界读取超大文件。
- 返回媒体文件时设置正确的 `Content-Type`、文件大小和缓存头。
- FFmpeg 路径可通过 `FFMPEG_PATH` 配置。
- FFprobe 路径可通过 `FFPROBE_PATH` 配置。
- 生成临时文件时使用独立临时目录，并保证异常清理。

### 7.5 API 设计

建议按资源划分 Route Handler：

| 资源 | 路径 | 主要操作 |
| --- | --- | --- |
| 作品 | `/api/workflows` | GET、POST、PATCH、DELETE |
| 素材组 | `/api/assets/groups` | GET、POST、PATCH、DELETE |
| 素材 | `/api/assets/items` | POST、PATCH、DELETE |
| 模型配置 | `/api/model-config` | GET、PUT |
| 连接测试 | `/api/model-config/test` | POST |
| 参考预览图 | `/api/reference-overviews` | GET、POST、DELETE |
| 产品预览图 | `/api/product-overviews` | GET、POST、DELETE |
| 参考结构 | `/api/reference-structures` | GET、POST、DELETE |
| 生成规划 | `/api/generation-plans` | GET、POST、DELETE |
| 产品视频方案 | `/api/product-video-plans` | GET、POST、DELETE |
| 产品关键帧 | `/api/product-keyframes` | GET、POST、PATCH、DELETE |
| 产品分镜视频 | `/api/product-videos` | GET、POST、PATCH、DELETE |
| 最终视频 | `/api/final-videos` | GET、POST、DELETE |
| 视频合成 | `/api/final-videos/compose` | POST |
| 剪映草稿 | `/api/capcut-drafts` | GET、POST、DELETE |

所有接口应：

- 校验请求类型和必要参数。
- 使用合适的 HTTP 状态码。
- 返回统一、可读的错误结构。
- 使用参数化 SQL，禁止拼接用户输入。
- 生成类接口防止重复提交。
- 删除接口检查资源是否存在及归属关系。

## 8. 核心数据模型

### 8.1 主要实体

- `workflow_runs`：作品。
- `model_configs`：模型配置。
- `asset_groups`：素材组。
- `asset_items`：原始素材。
- `reference_overviews`：参考视频预览图。
- `product_overviews`：产品预览图。
- `reference_structures`：参考视频结构分析。
- `generation_plans`：参考结构的生成段规划。
- `product_video_plans`：面向具体产品的视频故事板。
- `product_keyframes`：关键帧候选版本。
- `product_videos`：视频片段候选版本及异步任务。
- `final_videos`：合成成片。
- `draft_assets`：剪映草稿附加素材。
- `capcut_drafts`：剪映草稿生成记录。

### 8.2 关系约束

- 一个作品可包含多个预览图、方案、关键帧和视频。
- 一个产品视频方案属于一个作品、一个参考预览图和一个产品预览图。
- 一个方案包含多个 Generation。
- 一个 Generation 可以有多个关键帧，但最多一个被选中。
- 一个 Generation 可以有多个视频片段，但最多一个被选中。
- 最终视频必须记录其来源作品与方案。
- 删除上级实体时，应明确采用级联删除还是阻止删除，不得留下孤立记录。

## 9. 非功能需求

### 9.1 易用性

- 新用户无需阅读代码即可理解创作顺序。
- 每一步说明输入、操作和预期输出。
- 错误提示告诉用户原因以及下一步怎么做。

### 9.2 稳定性

- 单个模型请求失败不能破坏已有数据。
- 异步任务状态应在刷新页面后恢复。
- 重复点击不会创建不可控的重复任务。
- 数据写入尽可能使用事务。

### 9.3 性能

- 列表接口不直接返回大体积 BLOB。
- 媒体文件通过独立文件接口按需读取。
- 视频任务轮询只查询未完成任务。
- 大型列表和媒体预览避免不必要的重复请求。

### 9.4 安全

- 默认只建议在可信本地环境运行。
- 公网部署前必须增加身份认证与资源权限校验。
- API Key 不得出现在客户端响应、日志或 Git 历史中。
- 上传内容需限制类型、体积和数量。
- 外部 URL 下载需防范 SSRF，并限制响应体积与超时时间。

## 10. Codex 实现计划

不要一次要求 Codex 完成整个项目。每个阶段都应先让 Codex 阅读当前代码和相关 Next.js 文档，再实现、测试和总结。

### 阶段 1：初始化与静态界面

目标：建立 Next.js、TypeScript、Tailwind 和基础工作台界面。

验收：开发服务器可启动；首页和作品详情页可访问；移动端布局可用。

给 Codex 的任务示例：

```text
请先阅读 AGENTS.md 和 node_modules/next/dist/docs 中与 App Router、页面和布局相关的文档。
然后为 AI Product Reel 建立首页和作品详情页的静态界面。先不要接数据库和模型接口。
完成后运行类型检查和构建，并说明改动文件与验证结果。
```

### 阶段 2：SQLite 与素材库

目标：实现数据库封装、素材组、文件上传和文件读取。

验收：上传素材后刷新仍存在；图片和视频可预览；删除行为正确。

### 阶段 3：作品隔离与预览图

目标：实现作品 CRUD、工作流隔离、参考视频抽帧和产品预览图合成。

验收：多个作品之间数据隔离；FFmpeg 抽帧与图片合成可用。

### 阶段 4：多模态结构分析

目标：实现模型设置、连接测试、参考结构分析和产品方案生成。

验收：配置有效时能得到 Markdown 方案；配置缺失或模型报错时有清晰提示。

### 阶段 5：图片生成

目标：解析 Generation，生成提示词并调用图片模型产生关键帧。

验收：每段支持多个版本，且只能选中一个版本。

### 阶段 6：视频生成

目标：提交异步图生视频任务，轮询状态并保存结果。

验收：刷新后可继续任务；成功、失败和重试流程完整。

### 阶段 7：成片与剪映草稿

目标：使用 FFmpeg 合并选中视频，并接入剪映草稿服务。

验收：成片顺序正确且可播放；草稿状态与错误可追踪。

### 阶段 8：质量收尾

目标：补充自动化测试、无障碍、错误边界、安全校验和文档。

验收：Lint、TypeScript、测试和生产构建全部通过。

## 11. 使用 Codex 的协作规范

每次向 Codex 提交任务时，建议包含以下信息：

1. 当前阶段和具体目标。
2. 允许修改的范围。
3. 不希望改变的现有行为。
4. 可验证的验收标准。
5. 要求运行的检查命令。

推荐通用提示词：

```text
请先阅读仓库中的 AGENTS.md、相关源码以及 node_modules/next/dist/docs 中与本任务有关的指南。

本次目标：<填写一个明确目标>
修改范围：<填写允许修改的模块>
保持不变：<填写不能破坏的行为>
验收标准：
1. <标准一>
2. <标准二>
3. <标准三>

请先检查当前实现，再直接完成修改。完成后运行相关测试、Lint 和生产构建，最后说明改动、验证结果以及仍存在的风险。不要提交密钥、数据库、生成媒体或本地缓存。
```

### 推荐迭代原则

- 一个任务只处理一个清晰的业务目标。
- 先让 Codex 阅读和诊断，再要求修改。
- 要求 Codex 提供可重复的验证方法，不只看页面截图。
- 每个阶段完成后提交 Git，保证随时可以回退。
- 新功能优先补充数据约束和错误处理，再完善视觉效果。
- 模型返回内容永远视为不可靠输入，需要解析校验和失败兜底。
