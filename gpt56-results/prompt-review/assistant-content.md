# assistant response

## 一、六个角度的评审

### 1. 产品内长期复用

**优点**

- 维度较完整：覆盖场景、构图、景别、产品状态、手部动作和展示目的。
- 兼顾“内容变化”和“叙事组合”，适合不同品类的视频拆解。
- 强调“粗略拆分、不逐帧分析”，有利于控制模型输出长度和调用成本。

**缺点**

- “主要镜头”“明显变化”“展示目的”等词缺少统一判定标准，不同模型或不同轮次可能拆分不一致。
- “包装到产品、整体到细节、静态到使用”等组合容易被模型理解成必须出现的流程，而非可选观察维度。
- 未规定时间格式、镜头边界和表格字段格式，长期批量使用时不利于程序处理。
- “产品展示方式”和“展示目的”有一定重叠，例如“手持产品展示”既可能是内容，也可能是目的。

**建议**

- 明确定义镜头切分优先级。
- 将“变化依据”分成“切分依据”和“描述维度”。
- 对展示目的使用有限的标准词汇。
- 固定输出为 Markdown 表格，禁止额外说明。

---

### 2. 模型视觉误判

**优点**

- 使用总览图而非逐帧视频，能让模型快速识别整体节奏和结构。
- 要求关注构图、景别、动作、产品状态，有助于避免只描述画面中的物体。

**缺点**

- 均匀抽帧会遗漏快速动作、短镜头和真实剪辑点；相邻格之间的变化不一定代表切镜。
- 模型可能把推拉摇移、手部移动、产品转动误判为新镜头。
- 总览图中画面较小，容易误判包装文字、材质、颜色、手部动作和产品细节。
- “展示目的”本身不可完全从画面确认，容易出现营销化臆测，例如把普通展示写成“突出高端质感”。

**建议**

- 明确区分“镜头切换”和“同一镜头内的运动或构图变化”。
- 不能确认时使用保守描述，如“展示产品局部，具体动作不确定”。
- 不要求识别品牌、文字、材质等小细节，除非在总览图中清晰可见。
- 展示目的应描述画面功能，不应推断消费者反应或营销效果。

---

### 3. 时间边界

**优点**

- 每格带时间，具备建立镜头时间区间的基础。
- 按时间顺序排列，便于后续生成剪辑结构或故事板。

**缺点**

- 未说明“开始时间”和“结束时间”是否包含边界。
- 未说明边界应以抽帧时间、推测剪切点，还是相邻镜头中点为准。
- 均匀抽帧无法精确确定真实切点，但原提示词没有明确“时间仅为近似值”。
- 可能出现镜头时间重叠或空缺，影响后续程序和故事板使用。

**建议**

- 采用半开区间：`[开始时间, 结束时间)`。
- 除最后一段外，后一段开始时间等于前一段结束时间。
- 以总览图中可确认的时间为准，不虚构毫秒级精度。
- 无法定位切点时，使用最近可见抽帧时间作为边界，并接受其为近似值。
- 最后一段结束时间使用视频总时长；若总时长未知，使用最后一个可见时间并标注“约”。

---

### 4. 输出一致性

**优点**

- 字段数量少，适合模型快速完成。
- 使用 Shot 编号有利于引用和后续编辑。

**缺点**

- “主要内容”可能有时写成物体清单，有时写成动作描述，粒度不统一。
- “展示目的”没有受控词表，可能出现“吸引观众”“增强信任”等不可验证表述。
- 未限定一段对应一个镜头，模型可能把多个并行变化写进同一段。
- 未规定一行一镜头、编号格式和时间格式。

**建议**

- 固定每个字段的表达职责：
  - 主要内容：场景、构图、景别、产品状态、动作。
  - 展示目的：该段在视频中的视觉或叙事作用。
- 建议使用受控目的词：建立场景、品牌/包装露出、展示外观、强调细节、演示功能、开箱拆封、使用过程、组合陈列、对比变化、收尾。
- 每个镜头一行，编号连续，不跳号。
- 不确定时保守描述，不新增字段。

---

### 5. 程序解析

**优点**

- Markdown 形式便于人类阅读，也能被简单程序提取。
- 五个字段相对固定，适合转成数据库或 JSON。

**缺点**

- 纯自然语言 Markdown 容易出现列数变化、换行、竖线字符、额外解释等问题。
- 时间格式不统一时，难以排序和计算时长。
- “Shot 1”与“镜头1”“S1”等混用会增加解析成本。
- 模型可能在表格前后添加说明、总结或注释。

**建议**

- 固定表头和列顺序。
- 时间统一为 `HH:MM:SS.mmm`，不足部分补零。
- 单元格内禁止换行和竖线；若必须使用竖线，改成顿号。
- 明确“只输出表格，不输出前言、结论、备注或代码块”。
- 如系统允许，最好同时要求内部遵守统一 schema，外部仍输出 Markdown 表格。

---

### 6. 后续故事板生成

**优点**

- 同时记录画面内容和展示目的，能为后续镜头复刻、产品替换和脚本生成提供依据。
- 覆盖从包装到使用、从整体到细节等常见产品视频结构。
- 不逐帧拆分，能够保留适合创作的高层结构。

**缺点**

- 当前字段缺少对“可复刻拍法”的明确描述，例如机位、镜头运动、背景和产品相对位置。
- “展示目的”如果过于抽象，故事板模型难以转换成具体画面指令。
- 没有明确哪些信息是视觉事实，哪些是创作推断，可能导致后续故事板继承错误判断。
- 粗略拆分若过度合并，可能丢失关键动作节点，如“拿起—打开—取出—使用”。

**建议**

- 在“主要内容”中稳定包含：场景 + 构图/景别 + 产品状态 + 关键动作。
- 不必新增字段，但应明确这些内容的顺序。
- 对故事板有价值的动作只在“改变产品状态或展示重点”时单独拆分。
- 不把推测出的拍摄意图写成事实；展示目的用简短、可视化、可执行的表述。

## 二、推荐的稳定版提示词

可改写为以下版本：

```text
你是一名产品视频镜头结构分析助手。请根据输入的“视频总览图”分析视频的主要镜头段落。

【输入说明】
- 总览图由视频按时间顺序均匀抽帧并拼接而成。
- 每个画面格带有对应时间。
- 总览图适合进行粗略结构分析，不适合逐帧或精确剪辑点分析。
- 请以总览图中实际可见的信息为准，不补充看不见或无法确认的内容。

【分析目标】
识别适合后续模仿拍法、替换产品和生成故事板的主要镜头结构。
不要把每个画面格都拆成独立镜头，也不要为了完整而过度拆分。

【镜头切分原则】
仅当出现以下一种或多种明显变化时，才考虑切分为新镜头：
1. 场景或背景发生明显变化；
2. 构图、机位或视角发生明显变化；
3. 景别发生明显变化，例如远景、中景、近景、特写之间切换；
4. 产品展示状态发生变化，例如包装、取出、展开、使用、组合陈列；
5. 手部动作导致产品状态或画面重点发生变化；
6. 画面目的发生明显变化，例如从建立场景转为展示细节或演示功能。

以下情况通常不要单独切分：
- 同一镜头中的轻微推拉摇移；
- 手部或产品的小幅移动；
- 相邻抽帧之间的轻微角度、位置或姿态变化；
- 不能确认是否发生切镜的变化。

【描述要求】
每个镜头的“主要内容”应尽量按以下顺序描述：
场景/背景 + 构图或景别 + 产品状态 + 关键动作。
只描述总览图中清晰可见的内容；无法确认时使用保守表述，如“展示产品局部，具体动作不确定”，不要臆测品牌、文字、材质、功能或营销效果。

每个镜头的“展示目的”应描述该段在视频结构中的视觉作用。优先使用以下词语：
- 建立场景
- 包装或品牌露出
- 展示产品外观
- 强调产品细节
- 演示功能
- 开箱或拆封
- 展示使用过程
- 组合陈列
- 对比变化
- 收尾展示

如有必要，可使用“展示产品外观并强调细节”这类组合表述，但不要写成消费者感受或营销结论。

【时间规则】
- 镜头按视频时间顺序排列。
- 时间格式统一为 HH:MM:SS.mmm。
- 以总览图中显示的时间为依据，时间边界为近似值，不要虚构精确剪辑点。
- 采用半开区间：[开始时间, 结束时间)。
- 除最后一个镜头外，后一镜头的开始时间必须等于前一镜头的结束时间，不能重叠或留空。
- 最后一个镜头的结束时间使用视频总时长；若总时长未知，使用最后一个可见时间，并在时间中写“约”。
- 如果无法确定某个变化是否构成切镜，优先合并为一个镜头。

【输出格式】
只输出一个 Markdown 表格，不要输出前言、总结、解释、置信度、备注或代码块。

表头必须严格为：

| Shot | 开始时间 | 结束时间 | 主要内容 | 展示目的 |
|---|---|---|---|---|

输出要求：
- 每行对应一个主要镜头；
- Shot 从 Shot 1 开始连续编号，不跳号；
- 一个镜头只占一行；
- 单元格内不要换行，不要使用竖线字符；
- 不要添加表格以外的任何内容。
```

## 三、额外建议

如果该提示词会被长期用于批量任务，建议在应用层再增加三项约束：

1. **预先传入视频总时长**：避免最后一段时间边界不完整。
2. **统一时间解析规则**：程序只接受 `HH:MM:SS.mmm`，并校验后一段开始时间等于前一段结束时间。
3. **设置最大镜头数或合并阈值**：例如总览图少于 20 格时通常输出 3–8 段，防止模型过度拆分。
